# 注册后密码/2FA 的原窗口会话恢复修复

## 范围与证据

只调整 Roxy 注册的已有 Session 恢复分支及进入密码/2FA 前的会话来源判断。保留原正常注册、邮箱 OTP、注册密码页、登录后补密码、MFA、分轮调度和界面实现，不新增开关、登录器或 Profile。

历史证据来自维护者指定邮箱对应的 Job 214，日志 `注册日志/3bf5712c-3b56-4e4a-952d-81f37b386ea6.log`。报告省略邮箱、代理认证、OTP 和 Token。

| 概率 | 待核对原因 | 证据与结论 |
| --- | --- | --- |
| 高 | 后台拿到 AT，原窗口 Cookie 仍缺失 | 60–69 行浏览器 Session 为 Failed to fetch；113 行后台恢复 AT；116/127 行为 cookie_import / cookie_auth_missing，读取 0 个 Cookie。确证为本例直接失败链路。 |
| 中 | 浏览器 Session 读取时机/网络波动导致恢复路径选错 | 旧代码只有 ChatGPTSessionExpiredError 走同窗恢复，普通 RuntimeError 超时直接后台登录。分支缺口确证；历史日志不足以区分最初 fetch 失败是短暂网络故障、导航还是登录态失效。 |
| 低 | 邮箱 OTP、密码接口或 MFA 拒绝 | 本例成功取得后台 AT，密码和 MFA 写操作尚未开始，故不将 cookie_import 错误归为补密码或 enroll/activate 拒绝。 |

37–38 行先进入邮箱验证码页，没有可用密码页链接。此时保留既有登录后补密码路径；本轮不强行调用未在页面流程出现的注册密码接口。

## Finding → Path → 修复

1. **同窗恢复条件遗漏普通 Session 超时**。`core/roxy_registration.py::_fetch_or_recover_chatgpt_session` 在已确认账号创建、且既有 ENABLE_2FA 开启时，也调用一次已有 `_recover_chatgpt_session_in_browser`。它继续用原 driver、原代理和原 OTP 历史排除规则；不增加循环重试或创建新 Profile。初次 Session 成功的路径原样返回；关闭安全设置的普通超时保持原后台 AT 恢复行为。
2. **后台 AT 被误当成可继续安全设置的浏览器会话**。`run_roxy_registration` 复用已有 `_at_recovery=email_otp_relogin` 标记，在创建 MFA 辅助会话前终止安全步骤，记录 `stage=browser_session / code=browser_session_not_restored`。账号和 AT 仍保存，security_ok 为 false；未确认的密码和 Secret 均不填充，后续使用原有“补密码/2FA”入口处理。
3. **恢复结果身份和取消边界**。恢复 Session 必须带非空字符串 AT，user.email 与目标邮箱忽略大小写并去掉首尾空白后完全一致；缺失/不匹配立即停止，不再后台登录掩盖。将既有布尔停止回调转换为抛错检查，覆盖恢复前、恢复过程中及恢复返回后；中止不会继续后台登录。
4. **恢复诊断**。本次调整的两处恢复失败日志只记录阶段及异常类型；身份/Token 门禁错误采用固定代码，并抑制原异常串联，避免将 Cookie/Token 异常正文带入新增错误。Session 读取失败不再一律宣称已明确退出登录。
