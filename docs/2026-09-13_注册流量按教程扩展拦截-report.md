# 注册流量按教程扩展拦截核对

日期：2026-09-13

## 结论

此前低流量模式只拦截 CDN 可选媒体，日志长期出现 `blocked=0`，界面显示的新增响应字节与代理商账单口径不一致。本次直接修改既有 Roxy Fetch 判定路径，补齐教程中可安全落地的遥测、可选身份和非必要一方资源拦截。

## 修改路径

- `core/browser_traffic.py::block_reason`
  - 保留 Cloudflare、Arkose、hCaptcha、reCAPTCHA、Sentinel 和 challenge 路径放行。
  - 新增已知遥测域：Datadog、Statsig、feature gates、Segment、Sentry。
  - 新增可选身份域：Google、Apple、Microsoft 登录资源。
  - 新增 ChatGPT/Auth/CDN 一方 image/media/font/manifest 拦截。
- `core/browser_traffic.py::RoxyTrafficOptimizer._install_fetch_cache`
  - 通过同一 Fetch handler 安装 image/media/font 资源模式与 manifest URL-only 模式；不新增并行拦截器。
- `tests/test_browser_traffic.py`
  - 更新安全资源放行、可选资源拦截、遥测查询串和 Fetch pattern 回归。

## 保留边界

认证页面、OAuth callback、Session API、MFA 请求、动态配置、Challenge 和 Sentinel 请求不进入缓存，也不因低流量模式被拦截。注册恢复分支仍会关闭 Fetch 并清空旧阻断状态。

## 真实日志根因与二次修正

20:16–20:19 的真实批次仍为 `downloaded=10,606,135–10,890,195`、`candidates=0`、`hits=0`、`misses=0`、`blocked=0`，并且安装错误明确为：

```text
Unknown resource type in fetch filter: 'Manifest'
```

这说明不是缓存内容没有命中，而是 Roxy 当前 CDP 在 `Fetch.enable` 校验 `Manifest` 枚举时拒绝了整组规则，导致教程要求的拦截和缓存均未生效。现已移除 `Manifest` 枚举：ChatGPT/Auth/CDN 一方 image/media/font 继续用已支持的资源类型模式，manifest 改用 URL-only `*manifest*` 模式，由既有 `block_reason()` 按实际 `resource_type`、路径和安全白名单二次判定；遥测和可选身份域继续使用 URL-only pattern。这样兼容旧版 Roxy/CDP，同时仍保留 challenge、Sentinel、OAuth callback、Session、MFA 和动态 API 的放行边界。

上游锁定 commit `68a1f8faede7e41f10ac5f9af267465fa61d0e3d` 的 Roxy 实现同样采用 URL pattern 的低流量规则，未把 `Manifest` 资源枚举塞入 Fetch filter；本地 2FA 实现继续与上游保持同一浏览器上下文、显式 `access_token`、enroll → TOTP → activate 顺序，未因流量修复改变安全流程。

二次修正验证：`tests/test_browser_traffic.py` 与注册/代理/OTP/Session 定向测试 `144 passed, 230 subtests passed`。下一批真实注册应重点确认 `errors=[]`、`candidates>0`、`blocked_by_reason` 非空及热缓存 `hits>0`，再用 `downloaded` 与代理账单对照。
