# 注册流量按教程扩展拦截核对

日期：2026-09-13

## 结论

此前低流量模式只拦截 CDN 可选媒体，日志长期出现 `blocked=0`，界面显示的新增响应字节与代理商账单口径不一致。本次直接修改既有 Roxy Fetch 判定路径，补齐教程中可安全落地的遥测、可选身份和非必要一方资源拦截。

## 修改路径

- `core/browser_traffic.py::block_reason`
  - 保留 Cloudflare、Arkose、hCaptcha、reCAPTCHA、Sentinel 和 challenge 路径放行。
  - 新增已知遥测域：Datadog、Statsig、feature gates、Segment、Sentry。
  - 新增可选身份域：Google、Apple、Microsoft 登录资源。
  - 新增 ChatGPT/Auth/CDN 一方 image/media/font/manifest 拦截。
- `core/browser_traffic.py::RoxyTrafficOptimizer._install_fetch_cache`
  - 通过同一 Fetch handler 安装资源类型模式；不新增并行拦截器。
- `tests/test_browser_traffic.py`
  - 更新安全资源放行、可选资源拦截、遥测查询串和 Fetch pattern 回归。

## 保留边界

认证页面、OAuth callback、Session API、MFA 请求、动态配置、Challenge 和 Sentinel 请求不进入缓存，也不因低流量模式被拦截。注册恢复分支仍会关闭 Fetch 并清空旧阻断状态。

## 验证

- `tests/test_browser_traffic.py`: 42 passed, 204 subtests
- 注册/代理/OTP/Session 相关回归：144 passed, 230 subtests
- 尚未执行真实注册批次；需要用代理商后台消耗、Roxy 阶段日志和 `blocked_by_reason/by_host` 做前后对照。

## 运行时回归修正

19:36 的真实批次出现 `candidates=0 hits=0 misses=0 errors=1`，确认首版把遥测/身份域展开成大量按资源类型的 CDP pattern，旧版 Roxy CDP 在 `Fetch.enable` 阶段拒绝了该组合，导致缓存与拦截器整体未安装。现已改为：一方资源继续按四种资源类型匹配；遥测和可选身份域改用 URL-only pattern，由同一个 `block_reason` 再做安全路径放行。并补充 `errors` 详细日志，避免安装失败只显示计数。

相关回归：`tests/test_browser_traffic.py` 与注册/代理/OTP/Session 定向测试共 `144 passed, 230 subtests passed`。
