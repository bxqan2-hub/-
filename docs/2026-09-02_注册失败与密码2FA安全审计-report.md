# 注册失败与密码/2FA 安全审计报告

## 结论

最新批次记录了 27 个任务，其中 22 个成功、5 个失败。失败集中在 Roxy 本地生命周期超时、代理链路不可用和 Email verified 回调尚未稳定三类；没有证据表明密码策略或 TOTP enroll/activate 本身导致本批次失败。

## 密码流程核对

**Evidence → Finding → Path**

- `validate_registration_password` 强制至少 12 位、大小写、数字和符号；固定密码与随机密码共用该校验。→ 未发现弱密码绕过。→ `core/registration_password.py`、`core/account_export.py::_setup_password_with_driver`。
- 密码页优先原生 submit click，观察成功终态后才继续；瞬态 input 卸载会等待 hydration，不会把 DOM 瞬态当作拒绝。→ 本批次成功日志均记录 `scheduled_click_async`/`scheduled_request_submit_async` 后进入 OTP；未发现重复提交导致的密码覆盖。→ `core/roxy_registration.py::_fill_password_page_if_present`。
- checkpoint 只在密码页确认离开或进入 OTP 后写入，错误字段出现时不落盘。→ 未发现“服务端未成功但本地标记已完成”的逻辑。→ `core/registration_password.py::persist_confirmed_registration_password`、`core/db.py::save_security_checkpoint`。

## 2FA 流程核对

**Evidence → Finding → Path**

- enroll/activate 均在当前浏览器网络栈执行，显式透传 access token，并校验目标邮箱与已认证邮箱一致。→ 未发现跨账号写入边界缺失。→ `core/account_export.py::_setup_totp_with_driver`、`_browser_authenticated_json_post`。
- 只有 `activate_enrollment` 返回 JSON `success=true` 才保存 TOTP Secret；只读 Token 校验失败单独记录，不回滚已确认的远端激活。→ 未发现“半成功被当成成功”的状态混淆。→ `core/account_export.py::_setup_2fa_result`、`core/account_security_service.py::_run_security_setup`。
- WebUI 敏感接口经过统一 session/授权码校验。→ 未发现未授权读取密码、Token 或 TOTP 的可达路径。→ `webui/auth.py::register_auth_routes`、`webui/app.py` 敏感字段 API。

## 已识别的凭据风险（非本批失败根因）

1. 正式账号 JSON/`extra_json` 会保存注册密码、Token 和 TOTP Secret 明文；本地文件被读取时可直接接管账号。建议部署时限制文件 ACL、加密磁盘并避免把运行数据纳入 Git。路径：`core/db.py`、`accounts/`、`注册成功的账号数据`。
2. WebUI 的显式“复制 2FA URL”会把 TOTP Secret 放入第三方 URL 路径；这是导出功能的设计风险，不影响 enroll/activate。默认“复制密码2FA”仍导出原始 Secret。路径：`webui/app.py::_account_password_2fa_url_line`、`webui/templates/index.html`。

## 验证计划

1. 运行 Roxy 生命周期和 session recovery 回归测试，确认 create 采用 45 秒、open/close 仍采用 15 秒，并确认 callback settle 与代理 stage 测试通过。
2. 运行密码、2FA、checkpoint 和 WebUI 授权测试，确认成功终态写盘、失败不写盘、敏感 API 仍需授权。
3. 观察下一批日志：`stage=proxy_transport` 应可直接统计坏代理；`/browser/create` 不应再出现 15 秒超时；Email verified 后应优先出现 `callback session 已在当前 Cookie 中稳定`。

## 新增案例：smiles_forlorn.9c 2FA activate

**Evidence → Finding → Path**

- 任务日志显示注册、密码、OTP、资料页和 access token 全部完成，失败只发生在 `stage=totp_activate`，且 `http_status=null`。→ 高概率是浏览器 execute_async_script/fetch 传输异常或 status=0；旧日志丢失底层异常细节。→ `注册日志/d19de9d0-2deb-44e6-9f21-d023913ab73d.log`、`core/account_export.py::_browser_authenticated_json_post`。
- enroll 已成功但 Secret 未写入账号，符合“只有 activate success=true 才保存”的安全边界。→ 账号可安全从账号页重新执行 2FA，不需要重新注册。→ `core/account_export.py::_setup_totp_with_driver`、`core/db.py::update_account_security_setup`。
- 修复增加同一 enrollment 的一次有条件重试，并等待下一 TOTP 时间窗；不重复 enroll、不切换代理、不提前保存 Secret。→ 降低边界时间码和浏览器瞬态失败；若再次失败，日志会包含脱敏 renderer/HTTP 诊断。→ `core/account_export.py`。
