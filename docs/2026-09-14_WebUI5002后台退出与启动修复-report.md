# WebUI 5002 后台退出与启动修复（2026-09-14）

## 症状与范围

- 用户要求始终使用 5002，并报告启动窗口自动隐藏后，过一段时间浏览器失去连接。
- 现场确认监听实际消失，不只是浏览器 Session 过期。18:47 启动的实例最后日志为 19:17 的正常后台检查；19:45 查询时已无项目 Python 进程、5002 无监听。
- 最近三小时 Application 1000/1001/1002 中没有匹配项目/Python 的崩溃记录。没有 traceback 仅表示未捕获到异常，不据此认定具体哪个宿主操作结束了进程。
- 本次仅调整既有 Windows 启动路径与启动测试，不改注册、邮箱、代理池、密码、MFA、支付或 WebUI 授权。

## 分级假设与证据

| 优先级 | 假设 | 核对结果 |
| --- | --- | --- |
| 高 | 隐藏的后台进程仍跟随启动宿主的 Windows Job 生命周期 | 对照实验确认旧 Start-Process 启动的 venv launcher 在宿主 Job 中；WMI 创建的同一 launcher 不在宿主 Job 中。具体历史退出事件没有完整追踪，保留归因边界 |
| 高 | 原端口启动失败时脚本偷偷换端口 | 确认：旧默认 5002 在 stop 失败后转 5001；这直接违背用户固定端口要求 |
| 中 | 反复执行启动脚本主动停止当前实例 | 原 start 调用 stop 替换实例，属于显式重启行为；未发现周期调用路径 |
| 低 | Flask 自动重载或注册任务结束关服 | web.py 明确 debug=False；模板重载不是服务进程重载。未发现定时关服或父进程轮询代码 |

### 生命周期对照

- 使用同一个 venv Python、同一个只写本地 JSON 的观测脚本，两者均隐藏且不监听网络。
- 旧 Start-Process：解释器父进程（venv launcher）`IsProcessInJob=True`。
- Win32_Process.Create：解释器父进程 `IsProcessInJob=False`。
- 两者解释器自身均可有 Job：这是 venv launcher 为其子解释器创建的内部进程管理关系，不应直接把解释器的 True 当作宿主继承。应沿父进程链核对。
- 两种探针在启动调用返回后都存活 30 秒，说明“能短暂在后台运行”不足以证明已脱离宿主。
- 微软文档明确区分普通子进程的 Job 继承与 Win32_Process.Create，并说明 KILL_ON_JOB_CLOSE 会终止关联进程及嵌套 Job；该机制与本机观测一致。[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

## 修复边界

- 删除 5002 → 5001 隐式回退，默认始终为 5002；原端口替换失败则报告失败，保留端口不变。显式端口参数接口保持原兼容性，本次实启只用 5002。
- 原启动块改用隐藏 WMI 进程创建，脱离调用任务的 Job；仍运行同一 web.py，同一目录与环境，同一授权、日志、HTTP 就绪检查和真实监听 PID 核对。
- 不新增自动重启循环、计划任务、开机自启或第二套 WebUI；真正崩溃仍应单独诊断，不通过无限重启掩盖。
