# 注册任务状态关联核对（2026-09-13）

## 现象

WebUI 曾把旧的失败任务显示为“密码/2FA 已完成，Codex 已完成或按配置跳过”，但该任务日志只到创建窗口或邮箱验证阶段。

## 原因分级与证据

- **高概率：同邮箱后续任务被错误关联。** `core/registration_service.py::_account_for_job` 在任务没有 `account_id` 时仅按邮箱查账号。任务 240（`注册日志/28a356a4-3131-4fda-a990-87bb83d4ad2d.log`）于 19:08:36 失败且未进入密码/2FA；同邮箱任务 250 随后完成注册并写入密码、TOTP。旧任务因此读取了后续账号的完整凭据和 `codex_status=skipped`，触发误导性文案。
- **中概率：并发/重试期间邮箱被复用。** 任务记录和账号记录是独立落盘，旧任务没有 `account_id` 时无法凭邮箱区分同邮箱的不同尝试。
- **低概率：前端缓存。** 当前 API 会重新计算 `get_retry_info`；复现无需浏览器缓存，排除为主要原因。

## 修复

保留无 `account_id` 的兼容邮箱回退，但要求账号 `created_at` 不晚于任务终态（`completed_at`/`started_at`）。后续注册产生的账号不会再改写旧失败任务的状态；显式 `account_id` 路径不变。

## 密码 / 2FA 安全核对

本次只修改任务与账号的关联判定，没有修改密码提交、TOTP enroll/activate、Token 透传或凭据落盘逻辑。现有流程仍要求密码确认后写入 checkpoint、enroll/activate 成功后保存 TOTP；失败任务不会因本修复获得密码或 Secret。
