## 相邻确证缺陷与边界

- **邮箱错误分级**：Yangyang 列表/详情 HTTP 401/503 原先返回 None，外层误写为没有新邮件。修复原 helper 与轮询异常路径，保留 `mail_list/mail_detail`、HTTP 状态或异常类型；真空列表与服务失败分开。
- **邮箱等待预算**：原外层未给 Yangyang helper 传剩余预算，每请求默认 20 秒且分页/详情叠加。修复逐请求读取总 deadline，并透传现有 timeout，不加新配置。
- **邮箱日志脱敏**：主题可能包含 OTP，Requests 异常可能包含私有取件 Token；不再输出原主题/异常正文/响应预览，保留受限诊断字段。
- **时间与消息排除**：ISO `Z`/offset 被截断，在本机离线复现 28,800 秒偏差；正常 API 条目漏用 `exclude_message_ids`。复用已有通用时间解析并在原条目循环过滤。现场邮件是无时区本地时间，这两项不是本批直接根因。
- **窗口实际出口**：Job 16 曾因窗口探测无响应而使用预检结果继续。依照项目既有隔离规则，删除预检充当窗口实测的回退，缺少/无效窗口 IP 独立标记 `proxy_isolation` 并终止；不混成邮箱/请求错误。
- **MFA 写操作重放**：删除旧 activate 对无状态、所有 5xx 的外层重试，避免不确定写结果被重复提交。明确暂时响应由一个 helper 统一管预算，始终复用同一 enrollment；每次 activate 生成当前窗口码，成功只接受 `success is True`。
- **新 Token 被 MFA 失败丢弃**：Job 17 补密码后同窗读到新 Token，enroll 503 中断返回，旧注册 Token 又被最终显式保存；后续自动与手动套餐查询均为 HTTP 401/token_revoked。当前修复把已匹配邮箱的 Session 读取结果与 MFA 写操作解耦：token-only checkpoint + 当前会话内存透传 → Roxy finally → 原最终保存。保持数据库“显式新凭据优先于旧 checkpoint”的原规则，不调整全局合并优先级。
- **其他套餐错误**：16:10:09/16:10:12 两条 TLS 临时失败，最终在第 2 次返回 HTTP 200/free；六个完整安全设置账号均查询成功。套餐字段不会覆写密码/TOTP。上述 token_revoked 两条来自同一个密码已完成、enroll 失败的账号，非新增两条注册失败。
