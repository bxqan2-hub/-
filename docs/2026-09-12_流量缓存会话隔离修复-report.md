## 结论与证据边界

本次调整的是 Roxy/Selenium 的资源拦截与共享响应回放，不是 gzip/brotli 压缩参数。公共 JS 源码相同不等于 Canvas/WebGL 执行结果或账号指纹相同。确认了缓存门禁、过期处理和拦截范围的缺陷；未读取生产缓存正文，也没有证明已发生账号状态串用，或证明注册失败由共享资源导致。

修改前只读快照：共享目录内 1,068 个 metadata 都指向 `chatgpt.com/cdn/...`，其中 1,045 个 JavaScript、23 个 CSS；均声明 `public, max-age=2592000`，未声明 `immutable`。新规则下它们全部不合格。文件不删除、不复制，schema 3 和 URL 门禁直接让旧条目失效。

流量日志样本（`注册日志/1e9a431d-78ed-417e-ad38-ec4b9baa0a37.log`，09:25:37）：真实下载 1,707,047 字节，逻辑下载 25,123,302 字节，回放 23,416,255 字节，37 次命中、382 次拦截。这说明旧策略削减幅度大，不说明每一次拦截都必要，也不证明共享指纹。

## Finding → Path → 修复

| Finding / 本地复现 | 原有路径 | 本次修改 |
| --- | --- | --- |
| Cookie 静态请求也能命中 URL-only cache；无查询/hash/MIME 严格门禁 | `core/browser_traffic.py::is_cacheable_request/is_cacheable_response` | 只接受精确 HTTPS `cdn.openai.com` 默认端口、无凭据/查询/片段、静态前缀、hash 文件名的 JS/CSS；拒绝 Cookie、Authorization、Proxy-Authorization、Range、If-*、X-* 及重新验证指令。ChatGPT 同源、auth、challenge、动态配置全部走本 Profile |
| public 即可共享，HTML 也曾通过 JS 缓存响应判断 | 同上、`StaticResourceCache.read/write` | 响应要求 status 200、public + immutable + 正生命周期、匹配 JS/CSS MIME；拒绝状态设置头、私有/变体、非通配 CORS 与凭据 CORS |
| max-age=1 的条目在 100 秒后仍受全局 TTL 放行 | `StaticResourceCache.read/write` | schema 3，保存并读取 expires_at；取 s-maxage 优先/max-age，扣 Age 与 Date 表示的年龄，受本地最大年龄约束；读回、真正 fulfill 前再检查过期 |
| 响应头黑名单遗漏新的身份/关联头 | `_sanitize_headers`、`_fulfill_cached_request` | 改为五类表示头白名单；剥离未知头，不重放状态/nonce/边缘 ID；仅合成回放使用 no-store，避免在浏览器内重启原始 max-age |
| 整域 telemetry/feature gates、身份站点、字体/图片/manifest 和登录后 JS/CSS 被粗拦 | `block_reason`、`install`、现有 Fetch 安装与回调 | 清空旧 Network URL 黑名单；只在 Fetch 中精准拦截公共 CDN `/assets/` 下无查询的 mp3/mp4/ogg/webm Media。其余正常联网；保留原浏览器缓存和 HTTP 压缩 |
| CDP URL glob 可能把查询参数中的媒体扩展当成静态媒体 | 同上 | 删除原粗粒度 URL 模式生成路径，复用唯一 Fetch handler 按 URL 和 ResourceType 解析；不新增第二套拦截器 |
| session 阶段还可能读写共享资源或阻断密码/MFA 应用壳 | `set_session_only`、暂停/响应/fulfill 回调 | 原 session 标记只停止共享缓存读写；等待后和读响应 body 后复查；释放挂起 lease，正常应用网络继续 |
| response_error_reason 存在但 status 为空被误认新请求 | `_on_request_paused/_handle_response` | 按 CDP 两类响应标志识别响应阶段，保留真实失败，不用其他 Profile 刚填充的 cache 伪造 200 |
| finalize 后迟到回调重新登记缓存 lease | `finalize` 及现有回调 | 先关闭已有 Fetch 状态，再释放 lease/禁用；等待与提交点复查，不新增生命周期开关 |

普通 Profile 内 Cookie、localStorage、IndexedDB、UA/Canvas/WebGL 运行状态，以及 OTP/Token/密码/MFA enrollment 状态不进入共享缓存。浏览器原生缓存仍归独立 Profile；本次未修改/伪造浏览器指纹、代理或挑战协议。

## 密码与 2FA 复核

仅复核现有实现，未修改远端写操作：

- `core/account_export.py::_setup_password_with_driver` 在已提交且观察到成功文案/可信完成回调才返回成功；`_setup_2fa_result` 对失败先抛出，成功后才 persist 密码 checkpoint。
- `_setup_totp_with_driver` 先核对目标邮箱，enroll/activate 复用同一 driver 与显式 Token；检查 secret/session_id 与更新后的邮箱/Token，activate 必须 `success is True` 后返回 Secret。
- `_setup_2fa_result` 在成功激活后保存 TOTP；末端只读 Token 校验与凭据写入分开，校验失败不撤销已完成密码/MFA。
- `run_roxy_registration` 新建 Profile → 窗口真实出口 → 一致性复核 → 安装 traffic；`create_profile` 保持 `randomFingerprint=True`。不存在以 cache 替代 Profile 的调用路径。跨进程出口 lease 仍未共享，应保持多进程串行。
- 定向注册/密码/MFA/生命周期回归由隔离测试执行，不注册实际账号，不输出 Cookie、Token、密码、Secret。

范围外已知口径：`core/roxy_registration.py` 的单行“Token 校验”日志传的是 `twofa_status == 'success'`，其含义是密码/MFA 已完成，而非 `validation_ok`；独立 `twofa_validation` 与错误字段仍保留只读校验结果。本次只记录，未混入流量改动。
