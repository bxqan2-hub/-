# 2026-09-15 账号规模性能优化

## 结论

1000 个账号附近的卡顿主要来自账号 JSON 热路径：账号页每 2 秒轮询一次套餐状态，而每次请求都会重复解析完整账号文件、装饰全部行并构造全量 revision；后台状态更新还会同步重写静态查看器。

本轮采用不改变业务字段和接口语义的最小优化：

- `core/db.py:_load_accounts` 按账号 JSON 的 `mtime_ns + size` 缓存解析快照；调用方继续拿到独立行副本，保存和外部文件变化会自动失效/刷新缓存。
- `list_account_plan_check_statuses` 保留原有状态字段集合和变更检测语义，只把全量 `json.dumps(list)` 改为增量 SHA-1 摘要，避免构造大型中间 JSON。
- `_render_static_viewer` 增加 1 秒节流；显式 `refresh_static_viewer()` 仍强制刷新，账号数据 JSON/TXT/token 持久化路径不变。

## 验证

- 冷读 `list_accounts_page(limit=50)`：约 73 ms；同进程缓存后约 4 ms。
- `list_account_plan_check_statuses(limit=50)`：约 43–45 ms，仍保留状态摘要校验。

- 未改端口 `5002`、代理、注册流程、密码/2FA、短信重试和流量压缩。
