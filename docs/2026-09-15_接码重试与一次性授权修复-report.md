# 2026-09-15 接码重试与一次性授权修复

## 结果

- 手动选择国家时，后续号码重试继续使用该国家；SMSBower 手动选择的 supplier ID 在每一轮 `getNumber` 请求中显式传递，不再因为失败集合而漂移到其他国家或供应商。
- Roxy Selenium 和 Browser Use 在手机号发送失败、短信超时、验证码被拒后，不再刷新/后退到旧的手机号页继续使用一次性授权事务。下一轮会重新申请 CPA/sub2/本地 PKCE 授权地址，清理/离开旧登录状态，重新完成邮箱登录，然后再取同配置的手机号。
- 非浏览器 `core/codex_oauth.py` 路径无法重新打开浏览器授权链接，因此只固定 provider/country/supplier；不伪造浏览器重登录。

## 修改路径

- `core/sms_provider.py:acquire_number`：新增可选 `provider_id`，覆盖默认配置值以固定一次取号链路。
- `core/roxy_codex_oauth.py:_do_phone_verification_if_present`：固定接码配置快照；失败后调用 `restart_authorization`；入口 `_run_roxy_codex_oauth_once` 生成新授权地址并重新 `_fill_email_and_otp`。
- `core/browser_use_codex_oauth.py:_do_phone_verification_if_present`：同样固定配置并调用重授权回调；入口 `_run_browser_use_codex_oauth_once` 重新申请授权地址并重新邮箱登录。
- `core/codex_oauth.py:_do_phone_verification`：固定 provider/country/supplier 透传，日志 provider 不再硬编码为 HeroSMS。
- 测试：`tests/test_sms_provider_configuration.py` 验证国家和 supplier 参数；`tests/test_roxy_codex_phone_classification.py` 验证两次取号保持手选配置、触发一次重授权且不调用旧页面刷新/导航。

## 上游与安全复核

- 已按 `docs/UPSTREAM_PROJECT_INDEX.md` 读取锁定上游版本；没有整文件覆盖。本地扩展点是一次性授权事务的生命周期和接码重试策略。
- 重试前仍取消旧 activation；成功仍仅在 OTP 验证通过后 `complete`。API key、Token、完整手机号和邮箱验证码不进入新增日志；配置快照只包含 provider/country/supplier。
- `invalid_auth_step` 仍立即停止，不继续消耗号码；配置错误、余额不足仍不盲目重试。
