# 本站端口控制台局部滚动卡住复核（2026-09-04）

## 对象与结论

本次对象仅为 `http://127.0.0.1:5001` 的本站 WebUI 控制台，不是 Roxy 注册浏览器。控制台弹窗原先通过 `body.modal-open` 把整个页面设为 `position: fixed`，同时任务日志、账号表格等区域继续使用独立 `overflow: auto`。两种滚动模型叠加后，浏览器会呈现“上面一部分固定不动、下面一部分仍能滑动”的分裂状态。

修复直接收敛现有 `webui/templates/index.html::updateModalScrollLock`：弹窗打开时仍锁住页面背景滚动，但不再把整个 `body` 从正常文档流切换为 fixed，也不再通过负 `top` 和关闭时 `window.scrollTo` 搬移页面。未修改 Roxy Profile、注册并发、代理、密码、2FA 或注册浏览器参数。

## 原因分级与证据

### 高概率：整页 fixed 与内部独立滚动容器叠加

- 修改前在真实 `5001` 页面打开任务日志后，计算样式为：`bodyClass=modal-open`、`bodyPosition=fixed`、`bodyTop=-76px`、`bodyOverflow=hidden`、`htmlOverflow=hidden`。
- 同一页面的 `.log`、`.jobs-table-v2-wrap`、`.accounts-table-v2-wrap`、`.outlook-import-body` 均是独立 `overflow: auto` 容器。整页已固定时，这些内部区域仍可滚动，现象与反馈一致。
- 代码路径是 `webui/templates/index.html::updateModalScrollLock`：旧逻辑记录 `modalScrollY`，写入 `document.body.style.top`，再给 `body.modal-open` 应用 `position: fixed`。

### 中概率：关闭弹窗时的强制滚动复位造成跳动或局部状态不同步

- 旧逻辑关闭最后一个弹窗后执行 `window.scrollTo(0, modalScrollY)`。在页面包含异步刷新表格和多个独立滚动容器时，这次强制复位只恢复主窗口位置，不恢复内部容器位置，容易放大“某部分没动、某部分已动”的感知。
- 修复删除这条人工保存/复位路径，浏览器继续维护正常文档流位置。

### 低概率：本站控制台 renderer/GPU 崩溃

- 当前日志检索到的 `Timed out receiving message from renderer` 和 `script timeout` 均位于 Roxy 注册自动化日志，属于 ChatGPT 注册页面的 Selenium/Roxy 路径，不是本站 `5001` 控制台的 renderer 证据。
- 控制台真实页面仍可响应弹窗关闭和侧栏操作，未观察到页面进程崩溃、整页失去响应或脚本执行中断，因此该方向不作为本次修改对象。

## 修改与安全边界

- `webui/templates/index.html::updateModalScrollLock` 删除 fixed-body、负 top 和关闭时滚动复位，保留 `body/html overflow=hidden` 的背景滚动锁。
- `tests/test_webui_helper_regressions.py::test_modal_scroll_lock_does_not_fix_the_whole_page` 固定上述行为，防止以后重新引入整页 fixed。
- 没有新增配置项、环境变量、API 字段、函数、类或模块。
- 没有改动 `core/roxybrowser_client.py`、`core/roxy_registration.py` 或任何 Roxy 测试。
