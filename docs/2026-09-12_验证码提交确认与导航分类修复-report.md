## Finding → Path → 修复

1. **点击被误作提交确认** → `core/account_export.py::_password_submit_code`：删除固定 0.5 秒伪确认，保留监听直至匹配响应、真实页面推进或原有预算耗尽。点击后只观察，不重复输入/点击；无确认返回 `submit_unconfirmed`，已见 POST 未见响应返回 `request_pending`，HTTP/拒绝保持独立分类。
2. **网络回调乱序丢失响应** → 同函数 `observe`：本机 Selenium 的 CDP 回调采用独立线程，response 回调可能早于 request。局部锁保护小容量 request-id/HTTP 状态关联，未匹配 POST 的响应不作为提交确认；不读请求/响应正文，不消费共享 performance 日志。
3. **跨表单及模糊结果补点** → `_password_click_playwright`、`_password_find_submit_selenium`、`_password_click_selenium`：只选字段所属表单内可见/可用/非 aria-disabled/非 resend 按钮，移除全页按钮和 Enter 备用动作。点击异常可能发生在派发之后，只记录异常类，由状态机观察结果，避免另一次动作。
4. **注册 OTP 关键按钮的随机坐标点击** → `core/roxy_registration.py::_click_continue`：限定 OTP 表单，排除 resend，单次原生 WebElement 点击；不在异常后连续补点。
5. **Chrome 导航失败混为页面超时** → `_wait_email_submit_next_state`：轮询及 deadline 边界复用既有浏览器错误页识别，明确 `stage=email_navigation type=browser_navigation_error`，不自动重开认证或重发邮件。
6. **诊断落盘/日志泄露** → 删除 `_password_screenshot` 及调用，使用已有结构化状态和错误码，避免失败原图保留邮箱/OTP。`_follow_reauth_with_driver` 超时不含完整 URL；`_validate_2fa_token`、`_snapshot_otp_history`、`_setup_2fa_result` 的相关异常只保留类型，移除原文/traceback输出。

## 密码与 2FA 边界复核

- 初始重认证仍先精确匹配目标邮箱；邮件历史水位/消息 ID 排除及既有收信预算透传保留。
- 点击或 HTTP 200 均不直接保存密码；仅密码成功终态才执行原 checkpoint。
- 补密码后仍同步当前浏览器 Cookie、弃用旧 AT，同窗/同代理读取 Session 并匹配邮箱。
- enroll 需有效 Secret/session_id，activate 必须 `success is True` 才保存 Secret。
- 只读 Token 校验失败与 MFA 远端写入分开，不重新 enroll、不丢弃已确认 Secret。
- 不放松独立 Profile、随机指纹、真实出口原子占用/冷却/漂移保护；多个运行进程仍需串行。
