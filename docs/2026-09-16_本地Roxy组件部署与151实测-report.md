## 随机指纹：是，但不是所有参数都随机

已有客户端 `create_profile` → 本地 `/browser/create` → `createProfileOnDisk` → `buildFingerprint` → 加密 `lumi.conf` → 指定版本 RoxyChrome 读取。

| 项目 | 当前行为 | 来源 |
| --- | --- | --- |
| Profile ID / 数据目录 | 每次独立 32 位 hex；任务记录增加 local- 所属后端前缀 | 上游 ID + 本地归属适配 |
| 设备名、MAC、窗口名/标记 | 每次生成 | 上游指纹生成器；本站原随机名称透传 |
| CPU 核数、设备内存、屏幕、GPU | 从上游候选集合随机抽取，可能重复 | 上游，不承诺每个字段唯一 |
| Canvas、Audio、ClientRects、WebGL 噪声 | 每 Profile 生成参数；Canvas/Audio 另有扩展和 CDP shim | 上游，本次保留 |
| OS | Windows 10/11 中选择；本地模式不模拟 macOS/Linux | Windows 组件的限制，本站转换 |
| Chrome/驱动版本、UA 主版本 | 依据 ROXY_CORE_VERSION；只有 latest/未指定才选已安装最新版本 | 本次内核选择补丁 |
| 语言/时区 | 根据实测代理出口国家确定默认语言，Accept-Language 同语言；时区取实际出口 IANA 值 | 用户追加需求；ICU/CLDR，非随机 |
| Cookie/代理 | 不从最新 Profile 继承；独立新目录，代理仍来自本站原选择/预检路径 | 本次干净骨架及协议适配 |

两次空白窗口烟测的真实内核都是 151；CPU 核数分别 4/6、shim seed 分别 1333326304/761762524。在第一个窗口写入合成 fixture Cookie，第二个窗口没有该 Cookie。两者结束后均已删除。真实注册的 Profile 也为另一个独立 ID。

**不是只换 API 地址。** 官方 App 原本通过其 API 创建/启动环境；现在可由本地 Node 服务生成配置并直接启动已安装的 RoxyChrome。上游 Canvas/Audio 脚本是额外浏览器行为，与此前删除的本站通用页面属性注入 helper 不同。未声称两种后端指纹表现完全相同，也未把随机配置等同于已验证每个 Web API 的可见噪声。

## 哪些是本次修改

1. `core/roxybrowser_client.py`：沿既有客户端接口添加本地模式、按需隐藏启动/健康检查；本地独立端口、无官方 Token；转换 proxyInfo、headless、效率参数、工作区响应及关闭删除协议。新客户端快照模式，`local-` ID 让停止/GC 在切换后仍清理正确后端。用户追加地区匹配后，将原代理预检的 country/timezone 透传 create_profile；显式本地代理也预检，直接手工 create API 无代理则保留默认。缺少国家/时区在创建前记录独立 local_fingerprint_geo 错误。
2. `config/roxybrowser.py`、`.env.example`、`webui/config_editor.py`、`webui/templates/index.html`：一项 bool 开关；不新建注册执行器、邮箱实现或安全设置路径。原 ROXY_CORE_VERSION 继续作为唯一内核配置。
3. `core/browser_cache_service.py`：本地模式仅盘点本项目 data/roxy_local，官方模式保留原范围；无效或不完整盘点仍停止整目录清理。
4. 上游 `scripts/paths.mjs`：注入项目专属 Profile/temp 根目录，安装目录/内核仍从 Roxy 安装位置发现。
5. 上游 `scripts/fingerprint.mjs`：指定内核版本选择、ID/目录归属校验、代理 URL 编解码、构建失败前不建目录、默认从干净 skeleton 而非最新 Profile 派生。buildFingerprint 增加 ICU/CLDR 地区语言与 IANA 时区验证；国家语言不从代理域名猜测，多时区国家不套国家默认时区。原随机生成器和候选表保留。
6. 上游 `scripts/roxy-api.mjs`：localhost Host/Origin、POST JSON、严格解析、健康服务标识/目录、Node 版本检查、路径含空格兼容；匹配内核/driver；合并同时 open、处理启动失败、等待关闭、删除噪声临时目录。

没有修改官方 App/asar/内核、没有运行上游 tools 中的修补脚本。其他 upstream CLI/诊断工具仅保留作来源资料，本站没有引用它们作为第二个运行入口。

## 追加地区匹配与官方软件对照

首轮成功后，用户要求按代理所在地自动匹配。直接修改本地生成路径，不新增第二个开关：

`原 probe_proxy_exit_geo → country/timezone → open_profile/create_profile → POST /browser/create → buildFingerprint → lumi.conf + 启动语言参数`。

- 实测出口国家用于选择 ICU/CLDR 的地区默认语言；多语言国家这是默认选择，不是对用户语言偏好的推断。
- 时区严格使用预检结果，不从国家推断（例如 US 的 Chicago 与 Los_Angeles 均有独立用例）；ICU 校验 IANA 区域，不使用固定数值偏移，夏令时由浏览器处理。
- 新本地 Profile 有代理时总是读取实际出口，包括显式本地代理入口。不改官方模式的预检语义。缺少国家/时区或非法时区在创建前失败，不继续固定纽约指纹；直接手工 create/无代理模式的上游 locale 默认保留。
- 先做同一代理、Windows/151 的两后端空白页面对照；发现上游的回退语言列表不同，已将自动模式 acceptLang 调整为单个地区语言。随后重新在同代理 HTTPS 页面验证，不拿不安全 about:blank 上不可用的 deviceMemory 值当成指纹故障。
