## 原因分级与 Finding → Path

### 高概率：补密码验证码提交/过渡状态误判

`core/account_export.py::_password_visible_selenium` 只返回 visible 且 enabled 的输入。旧 `_password_submit_code` 遇到无匹配输入或键入异常立即 False；`_setup_password_with_driver` 仅隔 0.75 秒重试一次，随后结束；已提交分支在 8 秒后报 not_advanced。

修复前使用真实 helper、虚拟 Driver 和虚拟时钟回放：禁用 3 秒的输入于 0.75 秒失败；输入后自动提交造成 stale、3 秒后导航的场景于 0.75 秒失败；10 秒后导航的场景于 8 秒失败。密码补设失败后，`_setup_2fa_result` 的必经前置检查阻断 MFA，解释两项同时缺失。

### 已确认：任务重试错误地转向 Codex

`core/registration_service.py::get_retry_info` 原本只要存在账号，就将失败显示为部分成功并推荐补跑 Codex。内存重放今日 7 个任务，7/7 返回 `retry_action=codex`。真实执行路径 `retry_job` 也只派发 Codex，不会补密码/TOTP。

账号列表 `webui/app.py::_compact_account_for_list` 原本未展示 `extra_json.twofa.error`，只展示独立补设任务的 `security_setup_*`，进一步隐藏了注册安全失败原因。

### 中概率、非本批直接根因：独立补设后的旧 Token

`core/account_security_service.py::_run_security_setup` 补密码后仍沿用补设前 Token。密码操作可能吊销旧 Token；这与注册主链已经同步 Cookie、读取当前 Session 的行为不一致。修复该既有补设入口，避免修正重试路由后进入相同的后续缺陷。

- 邮件一直未到：7 个都已拿到新邮件验证码，排除。
