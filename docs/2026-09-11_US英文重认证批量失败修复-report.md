## Finding → Path → 修复

1. **进入页面即重发，且语言分支不一致** → `_setup_password_with_driver` / `_PASSWORD_RESEND_JS`：先等待初始邮件，仅真实收码超时、同一有效挑战页、剩余预算充足时重发一次。接口错误、网络错误、挑战已变更或过期均不触发重发。重发时间戳在点击前采集，英文与越南语使用同一路径。
2. **未输入就误报验证码拒绝** → `_password_code_page_state` / `_password_submit_code`：验证码错误、认证页错误和普通提示分开；`Try again`、`Error messages` 等文案不再直接命中拒绝。新密码表单优先，disabled 输入框仍作为可见表单等待，不当作错误页。失败复用已有截图位置 `run/password_setup_failed.png`。
3. **最后一位自动提交后又点击** → `_password_submit_code`：使用当前浏览器的被动请求/响应监听，记录本轮 POST 身份与 HTTP 状态；已观测提交则不再点击。观察器不可用时不猜测补交，而由页面推进确认或以 `submit_unconfirmed` 结束。Email 精确匹配已知 validate 端点，TOTP 保守跟踪同源 accounts POST；TOTP 测试端点是合成 fixture，不是实际抓包结论。
4. **提交异常缺少分类** → 原 helper 返回值与两个调用点：区分 `page_error`、`rejected`、`http_failed`、`request_pending`、`submit_unconfirmed`；响应只接受本轮已记录 POST ID，日志只保留路径枚举、控件数、请求数、HTTP 状态和错误类型。
5. **重认证起点加强邮箱绑定** → `_PASSWORD_REAUTH_JS` / `_PASSWORD_REAUTH_SELENIUM_JS`：当前 Session 邮箱必须匹配显式目标邮箱，之后才允许请求 CSRF/signin。Node 回归确认错配场景只有一次只读 Session 请求，零 signin。

## 密码与 2FA 安全复核

- 密码仍只在成功终态后写入 checkpoint；未推进、页面错误或请求不确定均不落盘为成功。
- 2FA enroll/activate 顺序、同窗 Cookie/代理、显式 Token、邮箱绑定保持原边界；仅激活确认成功后保存 TOTP Secret。
- 只读 Token/套餐检测与远端密码、MFA 写操作结果独立，HTTP 200 套餐查询不代表密码或 2FA 成功。
- 观察器不读取/保存请求正文、响应正文、Cookie、Authorization、验证码或密码，不 drain `performance` 日志；结束时只移除自身 callback，不影响原流量统计监听。
- 新增日志脱敏测试覆盖邮箱、查询字符串、验证码、密码和 Token。已有失败截图属于运行数据，不入 Git。

### 实测追加 Finding：Windows 原子替换

- Evidence：Job 96、98 在远端成功后，`注册成功的邮箱.json.<uuid>.tmp → 注册成功的邮箱.json` 报 `PermissionError [WinError 5]`；Job 100 的套餐入队也遇到同类错误。
